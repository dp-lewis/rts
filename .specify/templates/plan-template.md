## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Each gate below maps to a principle in `.specify/memory/constitution.md` (v1.1.0). Mark
PASS / FAIL / N-A with a one-line justification. Any FAIL must either be designed away or
recorded in Complexity Tracking below.

- [ ] **I. Deterministic Simulation Core** — Does any simulation code this feature adds
      read wall-clock time, use unseeded randomness, iterate unordered collections, or call
      a forbidden transcendental (`sin`/`cos`/`tan`/`atan2`/`asin`/`acos`/`log`/`exp`/`pow`)?
      Is the same-seed-same-input-same-hash property covered by a test that runs across the
      full supported-platform matrix (Node LTS on ubuntu + macOS, and Chromium)?
- [ ] **II. Simulation–Presentation Separation** — Does the simulation layer stay free of
      rendering, audio, input, and UI dependencies? Does player intent enter only as
      commands queued for a future tick? Does it still run headless?
- [ ] **III. Test-First Development** — Does the plan schedule tests before the
      implementation they cover? Is simulation logic covered by headless state assertions?
- [ ] **IV. Replay-Verified Regression** — For each defect this feature fixes, is a
      recorded command log plus expected state hash committed as a regression case?
- [ ] **V. Simplicity and YAGNI** — Is every new abstraction, layer, configuration point,
      and third-party dependency justified by a present need rather than an anticipated one?
